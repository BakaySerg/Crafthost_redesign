Open a Support Request.

When submitting a support request, provide enough information for the engineering or support team to understand the issue without unnecessary back-and-forth.

Include:
  • Affected service
  • Clear description of the issue
  • When the issue began
  • Current symptoms
  • Error messages, where applicable
  • Recent infrastructure or application changes
  • Troubleshooting already performed
  • Operational or business impact
  • Appropriate contact for coordination
Do not include:
  • Passwords
  • Private keys
  • Authentication tokens
  • API secrets
  • Unnecessary confidential data

Support Request Priorities.

Communicate the Operational Impact Clearly.
Support priority should reflect the actual service impact.

Critical

Use for severe production-impacting incidents where a critical service or infrastructure environment is unavailable or materially impaired.

Examples may include:

  • Major production outage
  • Critical infrastructure unavailable
  • Severe connectivity failure affecting production
  • Significant service disruption requiring urgent engineering attention

High

Use for substantial degradation or operational problems affecting an important production service without complete loss of service.

Examples may include:

  • Major performance degradation
  • Partial infrastructure failure
  • Significant operational impact
  • Redundancy loss creating elevated production risk

Normal

Use for non-critical technical issues that require investigation but do not materially disrupt production.

Examples may include:

  • Configuration questions
  • Minor service issues
  • Non-critical monitoring concerns
  • Routine troubleshooting

Service Request

Use for planned or administrative requests.

Examples may include:

  • Infrastructure changes
  • Capacity changes
  • Access changes
  • Configuration requests
  • Scheduled maintenance coordination
  • General service questions

What Crafthost Support Covers.

Support Is Defined by the Managed Engagement.

Crafthost support can cover technical and operational responsibilities associated with the selected infrastructure service.
Depending on the agreed service scope, this may include:

  • Infrastructure monitoring
  • Performance analysis
  • Operating-system management
  • Capacity coordination
  • Security controls
  • Backup and recovery operations
  • Patch coordination
  • Network troubleshooting
  • Vulnerability management
  • Change management
  • Incident investigation
  • Infrastructure lifecycle operations
  • Infrastructure troubleshooting
  • Technical escalation

Support scope is not identical across every service.
Operational responsibilities, escalation paths, service boundaries and applicable service levels are defined according to the selected service and contractual engagement.

01 / Support & Operational Accountability

Infrastructure problems become harder to resolve when ownership is unclear.
Crafthost managed engagements are designed to establish clearer responsibility boundaries around the infrastructure layer.

Depending on the selected service, Crafthost may assume defined responsibility for areas such as:

  • Monitoring
  • Performance
  • Maintenance
  • Capacity
  • Security
  • Recovery
  • Operating systems
  • Change coordination
  • Incident escalation
  • Infrastructure lifecycle management

Infrastructure problems become harder to resolve when ownership is unclear.
Where an issue involves systems outside the Crafthost-managed scope, the support process should identify the boundary and support technical coordination where applicable.

02 / Planned Changes & Maintenance

Changes to production infrastructure should be controlled and traceable.

Support may be used to coordinate:

  • Planned maintenance
  • Resource upgrades
  • Operating-system changes
  • Security changes
  • Network changes
  • Capacity increases
  • Reboots
  • Infrastructure modifications
  • Migration activities
  • Recovery operations

Where applicable, change requests should include:

  • Requested change
  • Affected services
  • Preferred timing
  • Expected impact
  • Dependencies
  • Required approvals

Planned changes remain subject to the applicable service scope and operational process.

03 / Security-Related Support

Contact Crafthost Support promptly when you identify a potential infrastructure-security issue affecting a managed environment.

Relevant situations may include:

  • Unexpected administrative access
  • Suspected unauthorized changes
  • Suspected credential compromise
  • Infrastructure exposure
  • Unusual network activity
  • Vulnerability concerns
  • Security alerts
  • Firewall or access-control issues

Do not publicly disclose sensitive infrastructure details while an incident is being investigated.
Where the issue is production-impacting or security-critical, use the appropriate incident escalation path.

Security & Compliance Contact Support

04 / Backup & Recovery Support

Backup and recovery capabilities vary according to the service and selected options.

Support can help customers understand:

  • Available backup coverage
  • Recovery procedures
  • Backup schedules
  • Recovery limitations
  • Retention
  • Relevant service responsibilities
  • Restoration requests

Do not assume that every Crafthost service includes identical backup or recovery coverage.
For critical workloads, backup and recovery requirements should be established before an incident occurs.

05 / Service Status & Maintenance Notices

Before opening a ticket for a broad service issue, review the Crafthost Status page.

It should provide information about:

  • Current incidents
  • Planned maintenance
  • Service degradation
  • Resolution progress
  • Infrastructure availability
  • Restoration notices
  • Network events

If the issue affecting your service is already identified, the Status page may provide the latest operational update.

View System Status

Before Contacting Support.

Where practical and safe, confirm:

  • Which service is affected
  • Whether the issue is continuous or intermittent
  • Whether the issue affects one system or multiple systems
  • The exact error message
  • When the problem began
  • Whether basic connectivity remains available
  • Whether configuration recently changed
  • Whether the issue is reflected on the Status page

Do not make uncontrolled configuration changes to production-managed infrastructure solely for troubleshooting purposes. When uncertain, contact Crafthost Support.
